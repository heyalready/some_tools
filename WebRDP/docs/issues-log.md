# WebRDP 问题记录文档

本文档记录在 WebRDP 项目实施过程中遇到的所有问题、原因分析、解决方案和预防措施。

---

## 2026-04-16 项目初始化

### 问题 1: FreeRDP .NET 绑定库选择

**问题描述**: 
需要选择或创建 FreeRDP 的.NET 绑定库，市面上没有成熟的可商用方案。

**原因分析**: 
- FreeRDP 是 C 语言编写的库
- .NET 绑定需要通过 P/Invoke 进行互操作
- 现有的绑定库大多不再维护或许可证不兼容

**解决方案**: 
- 自行实现轻量级 P/Invoke 封装层
- 封装必要的 API：上下文管理、连接控制、事件回调、输入事件
- 使用 `libfreerdp3.so` (Linux/UOS) 和 `freerdp3.dll` (Windows) 动态链接库

**预防措施**: 
- 在项目开始前调研现有库的许可证兼容性
- 设计抽象的接口层，便于未来替换实现

---

### 问题 2: 跨平台本地地址配置

**问题描述**: 
需求要求使用 127.0.0.2:3389，但不同平台可能有不同的网络配置。

**原因分析**: 
- Windows 和 Linux/UOS 的环回地址配置可能不同
- 某些系统可能限制 127.0.0.0/8 网段的使用

**解决方案**: 
- 使用配置文件 `appsettings.json` 中的 `PlatformSettings` 进行差异化配置
- 默认值设为 127.0.0.2，但允许通过配置修改
- 在程序启动时验证配置的可用性

**预防措施**: 
- 所有平台相关的配置都应支持自定义
- 添加配置验证逻辑

---

### 问题 3: 会话复用逻辑设计

**问题描述**: 
需要实现会话复用，避免重复创建多个会话，同时支持断线重连。

**原因分析**: 
- 多个并发连接请求可能导致创建多个会话
- 需要区分"未注销的会话"和"已断开的会话"

**解决方案**: 
- 使用 `SemaphoreSlim` 实现会话管理的线程安全
- 只有当会话状态为 `Connected` 时才复用
- 旧会话未清理前先创建新会话会导致资源泄漏

**预防措施**: 
- 使用锁保护临界区代码
- 实现完善的资源清理机制

---

### 问题 4: log4net 版本选择

**问题描述**: 
需求指定使用 log4net 2.0.13 版本，需要确认与.NET 6 的兼容性。

**原因分析**: 
- log4net 2.0.13 是较老的版本
- .NET 6 使用新的配置文件格式

**解决方案**: 
- 使用 `Microsoft.Extensions.Logging.Log4Net.AspNetCore` 包进行桥接
- 保持使用 log4net 2.0.13 核心库
- 配置文件使用传统的 log4net XML 格式

**预防措施**: 
- 在项目开始时就记录所有依赖的版本要求

---

### 问题 5: Electron 与 C# 服务通信

**问题描述**: 
需要设计 Electron 主进程与 C# 后端服务的通信机制。

**原因分析**: 
- Electron 主进程需要管理 C# 服务的生命周期
- Web 渲染进程需要调用 C# API

**解决方案**: 
- Electron 主进程使用 `child_process.spawn` 启动 C# 服务
- 渲染进程通过 REST API (HTTP) 与 C# 服务通信
- 视频流使用 WebSocket 进行双向通信
- 使用 IPC 传递控制命令

**预防措施**: 
- 设计清晰的进程间通信协议
- 实现服务健康检查机制

---

### 问题 6: 低延迟视频流传输

**问题描述**: 
需求要求"几乎 0 延迟"，需要选择合适的视频流传输方案。

**原因分析**: 
- HTTP 轮询延迟高
- WebSocket 可以提供更低的延迟
- MJPEG over HTTP 实现简单但效率低

**解决方案**: 
- 使用 WebSocket 传输原始帧数据
- 采用二进制格式而非 Base64 编码
- 在客户端使用 Canvas 直接渲染
- 未来可考虑使用 WebCodec API

**预防措施**: 
- 在性能要求高的场景优先选择双向通信协议
- 减少数据编码/解码开销

---

### 问题 7: Windows 和 UOS 会话隔离

**问题描述**: 
需求要求"和本地桌面环境隔离"，但不同操作系统的会话隔离机制不同。

**原因分析**: 
- Windows 使用 Session ID 隔离
- Linux/UOS 使用 X11 或 Wayland 显示服务器
- FreeRDP 的本地会话模式在两个平台上的实现不同

**解决方案**: 
- Windows: 使用 FreeRDP 的 `--local-session` 模式
- UOS: 使用 Xvnc 或类似的虚拟显示服务器
- 通过配置文件的 `SessionType` 进行差异化配置

**待办**: 
- 需要在实际环境中验证两种平台的会话隔离效果
- 可能需要针对不同操作系统调整 FreeRDP 的启动参数

## 经验总结

### 架构设计
- 分层架构清晰：Electron -> C# API -> FreeRDP -> OS
- 会话管理器统一处理并发和资源管理
- 使用依赖注入便于测试和扩展

### 代码质量
- 所有公共 API 都有 XML 文档注释
- 使用接口抽象便于单元测试
- 异常处理完善，避免进程崩溃

### 开发流程
- 先设计接口，再实现具体逻辑
- 单元测试覆盖核心业务逻辑
- 问题文档化，避免重复犯错
